# 要件定義

## 目的

Steam向けUnity製品へ採用する標準トランプゲームを、多数の候補からCPU試遊と自動検証で
比較する。検証用CLIとUnity製品は同一のC#ルール実装を使用する。

## 機能要件

| ID | 要件 |
|---|---|
| REQ-CARD-001 | 52枚デッキとカード文字列の往復を提供する |
| REQ-GAME-001 | 全ゲームが合法手、適用、終了、結果、プレイヤー表示を提供する |
| REQ-PLUGIN-001 | 独立ゲームをIDから生成し、人数範囲を検証する |
| REQ-HIDDEN-001 | 表示とCPU方策へ非公開情報を漏らさない |
| REQ-CPU-001 | 各ゲームに必ず合法手を返す完走可能なCPU方策を持つ |
| REQ-PLAY-001 | プレイヤー0対CPUをCLIで試遊できる |
| REQ-SIM-001 | 複数CPU戦の完走数、ターン、勝者、失敗seedを集計する |
| REQ-SEED-001 | CLIとUnityで同じseedから同じ状態遷移を再現する |
| REQ-OPTION-001 | ローカルルールを`key=value`で設定する |
| REQ-CAT-001 | 92候補の台帳を保持し、生成可能と正式ルール準拠の完成状態を区別する |
| REQ-RULE-001 | 92候補の採用ルール、合法手、状態遷移、終了、得点を仕様として保持する |
| REQ-RULE-002 | 完成ゲームは元ルール固有の選択を省略せず、人間とCPUが同じ合法手契約でプレイできる |
| REQ-RESULT-001 | 勝者、得点、理由、ターン数を共通形式で返す |

## 非機能要件

| ID | 目標 |
|---|---|
| NFR-DET-001 | `DeterministicRandom`によるランタイム横断の決定性 |
| NFR-EXT-001 | 新ゲーム追加時に既存ゲームを変更しない |
| NFR-ROB-001 | 非終了状態の合法手なしと最大ターン超過を検出する |
| NFR-PERF-001 | 通常ゲーム100試合を開発端末で60秒以内に完了する |
| NFR-UNITY-001 | Unity 2021.3以上、.NET Standard 2.1でコンパイル可能 |
| NFR-PORT-001 | Runtimeアセンブリに外部依存とUnityEngine依存を持たない |

対象外は製品版GUI、Steam SDK、オンライン対戦、永続セーブ、自由文交渉と物理的な
リアルタイム同時操作です。これらを含む候補は採用ルール仕様に従って決定的操作へ正規化します。
