# ADR-0001 ロードマップとマイルストーンによる継続開発

- Status: Accepted
- Date: 2026-08-16

## Context

ルール検証基盤の完了後は、構造化表示、Unity UI、永続化、CPU難易度、チュートリアル、
製品品質など、依存関係を持つ複数の機能を順番に実装する必要がある。会話の終了ごとに次の
作業を再選定すると、優先順位、完了条件、過去の判断が会話履歴へ埋もれる。

## Decision

- `docs/product/roadmap.md`を製品開発の優先順位と現在地の正本とする。
- 1つのマイルストーンを、明確な目的と停止条件を持つ継続作業単位とする。
- マイルストーン内は依存順に1タスクだけを`Ready`または`In Progress`にする。
- 完了判定には成果物だけでなく、契約テスト、互換性、必須検証を含める。
- M01～M08の個別マイルストーン文書を事前に用意し、完了時に将来計画を自動生成しない。
- 最終タスク完了時は、次の既存マイルストーンと最初のタスクを`Ready`へ昇格する。
- 通常依頼は1タスク、CodexのGoalは1マイルストーンを上限とし、次の実装前に停止する。
- 長時間のCodex作業ではバックログ全体ではなく、1マイルストーンだけをGoalにする。
- 永続的な開発規律は`AGENTS.md`、変化する進捗は`docs/product/`へ分離する。

## Consequences

- ユーザーは毎回次の技術タスクを選ばず、「ロードマップに従って続けて」と依頼できる。
- Codexは次タスク、範囲、完了条件、検証方法をリポジトリから復元できる。
- 各タスク完了時に進捗文書を更新する作業が増える。
- 個別文書でDecision Gateとした製品判断だけ、実装前に明示的な確認が必要になる。
